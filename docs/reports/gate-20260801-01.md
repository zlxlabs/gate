## 官方策略取舍

GitHub 的 [Secure use reference](https://docs.github.com/en/actions/reference/security/secure-use)
说明完整 commit SHA 是不可变 action release 的安全 pin；tag 或 branch 可能被移动。
[Reusable workflow 配置文档](https://docs.github.com/en/actions/concepts/workflows-and-actions/reusing-workflow-configurations)
说明跨仓 reusable workflow 中的 action 按 caller 仓库上下文执行，并且 reusable workflow
可用 commit SHA 固定 YAML 代码。

因此本任务保留跨仓形式，选择最小修复：三个内部 nested action ref 统一 pin 到本次发布
基线 SHA `9a7927410b8caef10d1c0ae5c31b3bb94bb1f5fc`。不能把 reusable workflow 自身改成
`./.github/workflows/...` 来“自引用”：GitHub 文档中的相对 workflow 形式指 caller 与
called workflow 同仓，跨仓 gate caller 仍必须使用 `zlxlabs/gate/...@<SHA>`。

这个 SHA 是本次改动的 release 基线 pin，不会回写旧历史 ref；未来发布必须先验证，再让
外部 caller 显式 bump 到本任务最终 release commit，并同步 runner group 白名单。

## 守卫实现

新增 `scripts/check_pinned_uses.py`，仅使用 Python 标准库：

- 默认扫描 `.github/workflows/**/*.yml|yaml` 与 `.github/actions/**/action.yml|action.yaml`。
- 只识别 `zlxlabs/gate/...@ref`；完整 40-hex SHA 通过，相对 `./` 不会被识别为跨仓内部 ref，
  外部 `actions@v4/@v5` 不会被误报。
- `--root PATH` 支持临时样本，`--include-templates` 可显式把模板加入扫描。
- 失败输出固定包含 `文件:行号:ref`，并返回非零。
- `.github/workflows/ci.yml` 在既有 `test` job 中增加一个 step，准确执行
  `python3 scripts/check_pinned_uses.py`，没有增加 job。
